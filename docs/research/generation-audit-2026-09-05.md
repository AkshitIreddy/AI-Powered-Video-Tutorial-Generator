# Generation, timing, and rendering audit — 2026-09-05

## Scope and method

This audit covers the authored storyboard path in `services/pipeline`, the renderer bridge in `services/renderer`, and the built-in scene compiler/renderers in `packages/scenes`. It compares the current tree with the preserved v1 code and `v1.0.0` tag, then checks current primary specifications, vendor API documentation, upstream implementation code, and directly relevant upstream defect reports. GPU-heavy generation was excluded from this code-audit phase. Subsequent provider smokes used one bounded request per explicitly authorized route, with no automatic retry; their outcomes are recorded below.

The v1 implementation used a one-pass provider response, scraped images, Edge TTS, randomly selected layouts, and shell execution. The current architecture is materially stronger: it has durable stages, immutable artifacts, closed schemas, deterministic seeds, a rational 240,000-tick timebase, renderer sandboxing, and explicit QA/approval gates. The remaining problems were integration correctness problems rather than a reason to return to v1.

## Implemented corrections

### One authored-scene path for preview and final render

The renderer's mature semantic resolver moved into `@alystria/scenes`. `sceneSpecFromStoryboard` now projects a persisted storyboard scene into that resolver. Both product preview and final rendering can therefore consume the same authored text, semantic units, layout intent, timing, and deterministic seed. This removes the prior preview path that substituted catalog specimens and changed only the title.

### Exact duration preservation

The native scene-preview bridge previously replaced an authored `durationTicks` value with `duration * 240000`, defaulting to one second when the legacy field was absent. It now preserves a positive JavaScript-safe integer `durationTicks` exactly and uses legacy seconds only when ticks are absent. Tests cover conflicts and invalid numeric values.

Measured narration is now authoritative when the storyboard clock is fitted. Production may add at most two seconds of unauthored visual tail per scene and at most six percent of the requested tutorial duration overall, whichever is smaller. Each scene records its exact `visualTailTicks`. A 180-second, five-scene lesson can therefore absorb at most ten seconds total; narration measuring 150 seconds fails with a request to revise and approve the pacing instead of manufacturing 30 seconds of finished-slide or presenter stillness. Only the explicit `ALYSTRIA_MEDIA_MODE=fixture` test route can retain longer synthetic padding, and it labels that source `fixture-duration-padding`. No successful current Magpie generation was available in the inspected portable project databases, so this correction does not infer or tune a Magpie speaking rate from unrelated voices.

### Reviewed storyboard approval is the media source of truth

The desktop already saves edited scene titles, narration, and objectives into the durable `payload.storyboard`, but approval previously copied the old approval-job result and every media stage read that old job again. A visible pre-approval edit could therefore disappear from TTS and final rendering. Approval now freezes those three reviewed prose fields from the exact current generation revision into a new immutable approval revision. The generated storyboard envelope, ordered scene IDs, durations, claims, types, and all other scene fields must match the generated approval payload exactly; stale heads, placeholder or reordered IDs, and structural mutations fail before any media work. Post-approval stages load only the immutable approval revision and require its generation ID, stage, and approved gate to match. The approval-job payload remains unchanged as historical evidence.

Measured narration pacing failures now have a bounded same-generation recovery path. After speech measurement fails specifically for excess duration or an unauthored visual tail beyond policy, the user may revise at least one narration field, save that review at the exact current head, and approve it again. Reapproval is refused while any job in the current media branch is ready, queued, running, or waiting to retry. Once the branch is terminal, its post-approval jobs become stale historical records and a new immutable approval revision records `supersedesApprovalRevisionId`; a complete post-approval graph is enqueued with the new approval revision in every action key. Status and retry select only the newest approval branch, while ordinary Retry keeps the same approved narration. The prior approval snapshot, artifacts, jobs, and events remain unchanged and inspectable.

### Honest narration timing provenance

The provider-neutral timing adapter previously accepted any same-count token list, labeled invented duration-proportional timings `COMPLETE`, and reported an aligned-token ratio of 1.0. It now compares normalized token identities in order. A mismatch or missing provider timing produces `ESTIMATED` timing with no aligned-token ratio. Renderer contracts allow the ratio to be absent for estimates, while final generation QA now raises a blocking major finding unless every narration scene has complete provider-native or forced-alignment evidence with full token coverage. Deterministic fixture speech supplies an explicit fixture clock so tests do not weaken this production gate.

Magpie narration now has a pinned local forced-alignment path. The workflow writes the exact transcript and narration assets for all untimed scenes, invokes one isolated ONNX Runtime CPU worker, then validates normalized word identity, complete coverage, finite monotonic non-overlapping intervals, and the audio-duration bound before recording `forced-alignment` evidence. One ONNX session serves the batch so model startup is not repeated per scene. The final QA gate remains fail-closed when the runtime is missing, a hash changes, or any token cannot be verified.

The original aligner worker dropped every character outside its alphabet. A raw `O(n^2)` therefore became the false acoustic target `ON`, while a digit-only word such as `1234` failed only after synthesis. No upstream provider or pronunciation layer guaranteed that mathematical notation had already been spoken out. The workflow now derives one deterministic English spoken form before synthesis and sends that exact same form to provider-native timing validation or forced alignment. It expands integers, decimals, percentages, fractions, signed and decimal powers, scientific notation, inequalities, common Greek symbols, roots, subscripts, factorials, ratios, and the tested Karatsuba expression `(a+b)(c+d)-ac-bd`. The immutable narration record retains both authored and spoken text, their hashes, and both word counts. Non-English provider-native routes retain their original narration; the English-only normalizer is not applied to them. Any remaining unsupported semantic symbol fails before TTS. The worker independently rejects residual non-vocabulary characters instead of partially deleting them.

### Authored whiteboard and live-code behavior

The structured education schema now permits `whiteboard` and `live_code` scene types and tells the writer when to choose them. Live-code rendering uses the active authored action, including run output and narration anchors, instead of hard-coded call/split/return decorations.

### Route-correct local generation and presenter opt-in

A persisted all-local routing policy previously replaced the usable local media client with a provider router that intentionally has no `local-runtime` adapter. Local image/narration routes now remain on the local media client; only non-local media routes use provider adapters, with per-capability local fallback for mixed policies. A local structured-writing route no longer constructs a cloud text client. Presenter work is now off unless the saved visual customization explicitly enables it, preventing an installed presenter runtime from launching for an ordinary project.

The exact local SDXL route now selects a supervised ComfyUI media client only for `local-runtime` plus `local/sdxl-base-1.0`. ### Durable playback, bindings, and edited export

A successful generation now promotes the actual rendered artifact to `exports`, records its media type and path in the export stage, and returns that delivery in the generation receipt. `editor.bindings.get` verifies each stage JSON object against its CAS hash and immutable revision links before returning path-free scene bindings. Its `renders` bindings reference the verified audiovisual master with exact per-scene source intervals, preserving animated whiteboard and live-code output without duplicating or re-encoding the master. `asset.resolve` returns a local path only for a registered, hash-verified raster image, audio, or video CAS object and rejects active SVG and document artifacts.

Edited timeline export now compiles a closed `alystria.editor.render.v1` manifest into shell-free FFmpeg argv and runs as a durable background job rather than holding the worker's 30-second RPC mutex. The service independently verifies that every input is either a generation-linked media artifact or a promoted import whose immutable asset/provenance records clear it for export; caller-declared `exportEligible` is never sufficient. The resulting master is added to CAS and an immutable project revision.
